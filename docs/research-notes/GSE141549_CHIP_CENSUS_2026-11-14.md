# Single-platform coverage of the clinically eligible Finnish cohort

**November 14, 2026 UTC · Metadata assessment · Issue #31.** Of the 38 eligible independent donors in native EndometDB, **32 have one raw measurement record for every HumanWG-6 v2 probe address**, including the physical FOSB probe ILMN_1730706 at address 6040086. Seven run-by-histologic-phase groups on this chip contain **12 cases and 13 controls**. This supports a prospectively specified FOSB comparison on a common physical probe. The census used assay IDs and probe addresses only. ## Complete raw coverage

The native PostgreSQL raw table contains 25,355,096 records covering 400 distinct assays, each linked by its declared foreign key to one of the 418 native assay records. All 38 preselected assay IDs occurred in the raw table. Exact equality to a complete manufacturer address set, plus exactly one raw row per address, was frozen as the criterion before acquisition. The WG-6 manifest contains 48,701 distinct addresses. HumanHT-12 v4 manifests R1 and R2 have 47,231 and 47,323 distinct addresses, respectively. Both HT-12 revisions assign FOSB to address 7160239. Seven verified WG-6 cells that contain both conditions include four proliferative cells (8 cases, 4 controls) and three secretory cells (4 cases, 9 controls). The other seven verified donors occupy cells with only one condition. Run and phase therefore matter for the estimand. Clinical eligibility was based on a hormone-medication field recorded as false with an unspecified lookback. The schema defaults this field to false. Controls were recruited during tubal ligation. These factors constrain comparability with other cohorts. ## Reproduction

The clinical gate and complete-manifest criterion were fixed at commit `d31d599` before outcomes. Source is the single ZIP/Deflate64 archive in Figshare v1, file 22809185, 2,955,844,826 bytes, publisher MD5 `e649e9231171e377e3a0e187e60b0abb`. The complete raw table occupied **512,593,465 bytes including PG framing** at uncompressed dump offsets [38,714, 512,632,179). The **512,595,211-byte ZIP prefix** covering physical bytes 0 through 512,595,210 has SHA-256 `74316094156c43ebb693c060178238b46c0b3f5fa032f8333488063da9e5ce7a`. The census checks that hash, the ZIP/PG boundaries, raw table tag, declared foreign key, PG terminator, zlib EOF and COPY terminator. It retains only the eligible address sets and reports aggregates. [Figshare manifest](https://api.figshare.com/v2/articles/12195975/versions/1) · [Offline program](../../scripts/audit_endometdb_chip_census.py)

Use the two clinical ranges and the three previously pinned manufacturer manifests in the [eligibility audit](GSE141549_ELIGIBILITY_2026-11-13.md). For a fresh offline run, supply a single exact ZIP prefix. Its SHA-256 is checked before any census result is returned.

```bash
cd data/private/gse141549
curl --fail --location --range 0-512595210 --max-filesize 512595211 \
  https://ndownloader.figshare.com/files/22809185 -o raw-prefix.zip.part
cd ../../..
python scripts/audit_endometdb_chip_census.py data/private/gse141549 \
  --prefix data/private/gse141549/raw-prefix.zip.part
python -m pytest -q tests/test_audit_endometdb_chip_census.py
```

The executed run reused `archive-start.bin`, `native-raw-continuation.bin`, and the beginning of `native-normalized-head-range.bin` from the preceding audit. The missing middle range 2,665,536 through 510,399,999 was retrieved as 64 ordered segments of at most 8,000,000 bytes, confirming HTTP 206, full-file length, inclusive byte offsets and exact response size. This added 507,734,464 bytes and took 139 seconds with four parallel transfers. The program reads these ordered fragments without creating a duplicate prefix if `--prefix` is omitted. The full census took 20 seconds on CPython 3.12.14 with inflate64 1.0.4, peak process RSS 678,608 KiB. No random procedure applies. Individual records, compressed source and raw outcomes remain outside Git.
