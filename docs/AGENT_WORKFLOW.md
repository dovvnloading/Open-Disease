# Agent research workflow

This is an **independent AI research workbench**, not an autonomous clinical study or coordinated laboratory. Its objective is to turn bounded AI time and compute into reusable source-backed computational work. No institution, grant, formal peer review, collaborator, or external outreach is a precondition for exploratory work.

## 1. Pick a question, not a vague mission

`research/tasks/*.json` is the queue. Each file has an ID, question, scope, primary sources, dependency IDs, steps, deliverables, acceptance criteria, priority, GitHub issue and an indicative compute/network limit. Use:

    python scripts/research_queue.py validate
    python scripts/research_queue.py ready

A task marked `ready` appears only when its dependencies are `done`. A task may remain `blocked` when source rights or metadata are insufficient. Task status is a **reviewed Git change**, not an assertion generated by merely starting a job. Work on separate branches/PRs to avoid simultaneous agents overwriting each other's claims. Reserve work in the linked issue/PR; avoid duplicate compute.

## 2. Use compute deliberately

Start with literature/source audit or cheap synthetic preflight. Favor a minimal baseline and a null/negative control over expensive model training. Each task states maximum runtime, RAM and download allowance; these are voluntary guardrails, not enforced limits. Network access to a public source is opt-in; a task entry **does not authorize** accessing restricted datasets, spending money, or starting downloads in an environment where network has not been authorized.

For GSE51981, the first real experiment follows `docs/GEO_MICROARRAY.md`: verify participant/group/phase/tissue mapping and data rights, preselect a published comparison, then run processed-microarray limma with official data. Stop if source information cannot substantiate the categories. Do not confuse successful synthetic CI with a biological result.

## 3. Leave a verifiable handoff

Create a local, Git-ignored run stub:

    python scripts/research_queue.py new-run --task gse51981-sample-audit --agent my-agent --out results/gse51981-sample-audit/run.json

Fill in the run record as work proceeds: actual code commit, commands, environment/package versions, UTC times, random seed, primary source URLs, retrieval dates, legal/access notes, **real** checksums where files were acquired, exclusions, negative controls, tested family, artifacts, measured runtime, memory/download usage, and outcome. Empty fields mean *unknown/not run*, never success.

In the PR, include a **public-safe** summary: task ID, question, methods and source links, execution status, important results including null/negative/failed, assumptions, reproducibility commands, acceptance-check outcomes and next dependencies. Record a blocker if work stops. Patient/sample-level artifacts and human-data-derived full matrices stay local/ignored, not in Git, Actions artifacts, or hosted AI context. Only publish aggregate results if source terms and privacy safeguards permit.

## 4. Evidence labels

| Label | What it establishes | What it does not |
| --- | --- | --- |
| `software-only` | Synthetic test or program behavior | Human disease biology |
| `source-audit` | Cited public literature/metadata assessment | New experimental observation |
| `exploratory-computation` | Analysis of eligible real public data with stated confounders | Independent replication, causation or medical utility |
| `independent-replication` | Separately sampled, properly comparable data support a specific predeclared result | A proven therapeutic target or clinical intervention |
| `experimental-validation` | Properly governed biological experiment supports a defined mechanism | Human clinical safety/efficacy |

The first three labels are the intended near-term output of this repository; the latter two are not promised. When external validation cannot be obtained, say `not independently validated` and keep the result exploratory. A knowledgeable reviewer can improve interpretation, but is **not a prerequisite** for a fully qualified source-audited exploratory report. Independent specialist and appropriate ethical/regulatory oversight become necessary for stronger biological, experimental or clinical claims; agents cannot self-certify them.

## 5. What requires the operator

No agent should contact a scientist, patient, institution, funder, or data custodian merely because a workflow mentions review. The agent may flag a **specific** case needing a decision: public source's reuse terms are unclear and no compliant alternative exists; a security or privacy incident requires private reporting; a restricted-data access request or prospective human study is proposed; or a claim would be used for medical decisions. State the reason, safer alternatives and minimal proposed action; obtain explicit approval before outreach. Otherwise log the limitation and pursue another public-data question.

## 6. What is success?

Reproducible agreement with published work, honest nonreplication, a corrected source/method error, a well-supported negative finding, or a useful tested research tool. An ever-larger agent framework, synthetic classifier score, or generated target list is not progress unless it clears a real evidentiary bottleneck.
